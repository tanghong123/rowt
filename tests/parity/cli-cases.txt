# The lifecycle arms — up, down, reload, restart. The ledger called these
# "proven by boot-test", and the boot test does run them: against a REAL
# sing-box, checking that the tunnel comes up. What it never does is compare
# them to the shell, and every one of them diverged when first asked to.
#
# They are safe here for the same reason the rest of the sweep is: sing-box is
# the fixture's fake, `networksetup` and `limactl` are shims, and the only
# process either side actually spawns dies immediately — which is precisely
# what makes the failure path the one being compared. `up` is the slowest case
# in the file (two 5s readiness waits and a settle, per side) and worth it: the
# failure path is where the proxy gets cleared, the intent gets stamped and the
# exit status is decided.
#
# NOTE the trap that keeps these ungatable under `PARITY_SCENARIO=router-up`:
# that scenario writes the HARNESS's own pid into host.pid so the router reads
# as running, and every one of these arms would then kill the gate. It is the
# same documented hazard as `reload`, and it applies to `down`, `restart`,

# Bare `up` chooses its own mode: no target named means `_direct_reaches_escape`
# curls the GFW canaries (the shim answers, so this is deterministic here) and
# then `probe` decides. Probe fans out one resolver call per server, so the
# trace is in whatever order the scheduler produced — compared as a SET, like
# every other case that forks.
PARITY_UNORDERED=1 up
down
reload
restart

# proxy on/off — safe to gate because BOTH sides funnel every system-proxy
# write through one guarded choke point, and the sandbox has no service anyway.
proxy off
proxy on
PARITY_SCENARIO=proxy-on proxy off
PARITY_SCENARIO=router-up proxy on
# …and the one scenario where `proxy on` really WRITES: its proxy points
# elsewhere, so the six networksetup calls run. Then the same with sudo refusing
# the way it does in a shell with no terminal (an agent's): ROWT_PARITY_SUDO=no-tty
# makes the shim answer in sudo's words, which both sides key the explanation on.
# Rust used to ignore a failed write here and carry on to the bypass list; no
# case could see it while the shim always agreed.
PARITY_SCENARIO=watch-proxy-repoint proxy on
PARITY_SCENARIO=watch-proxy-repoint ROWT_PARITY_SUDO=no-tty proxy on

# `watch install`'s one admin step. In the plain sandbox sudo reaches a shim that
# does not exist (no visudo), so the rule reads as invalid and the agent is still
# installed. Under no-tty, install stops BEFORE writing anything and says why.
watch install
ROWT_PARITY_SUDO=no-tty watch install
