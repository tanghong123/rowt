# Cases for `parity watch-shadow` — the watchdog shadow, end to end.
#
# Unlike watch-cases/*.json, nothing here hands the planner a hand-written
# observation. The shell builds it, the shell records its own actions, and the
# shell's own comparator judges them: this gate asserts the production shadow
# says `identical`, which is the claim PORTING.md §6.5's promotion rule rests on.
#
# One `ROWT_*=…`/`PARITY_SCENARIO=…` prefixed rowt invocation per line, optionally
# followed by ` | <substring the tick must log>` — proof the case reached the
# branch it was written for, rather than agreeing early and reporting a pass.
#
# The captive cases matter beyond the portal FSM: `_captive_proxy_off` WRITES the
# system proxy mid-tick, and the sandbox now models that write (shims/_recorder),
# so an observation rebuilt at EXIT reads a world the tick already changed and
# diverges. That is what makes the snapshot discipline testable here rather than
# only on a real machine — see selftest step 10b.
PARITY_SCENARIO=proxy-on ROWT_CAPTIVE_URL=http://127.0.0.1:8099/portal watch tick | captive portal detected — dropping system proxy
# A 200-inline portal names itself only in its BODY; both sides must pull the
# host out of it and print the 'hotspot add' line (task #46).
PARITY_SCENARIO=proxy-on ROWT_CAPTIVE_URL=http://127.0.0.1:8099/portal watch tick | captive portal host: portal.fakelounge.example
# …and an Aruba-style one names itself only on the hop AFTER a refresh back to
# the PROBE's own host, which is why #46 still found nothing at SFO (task #50).
PARITY_SCENARIO=proxy-on ROWT_CAPTIVE_URL=http://127.0.0.1:8099/aruba watch tick | captive portal host: portal.fakearuba.example
PARITY_SCENARIO=captive-episode ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | captive portal cleared
ROWT_CAPTIVE_URL=http://127.0.0.1:8099/redirect watch tick | opening its login page in the browser — http://portal.fake/login
ROWT_CAPTIVE_URL=http://127.0.0.1:9/x watch tick
# The only case that reaches phase two, and the one the netcheck observation
# exists for: the machine has MOVED (watch.net holds a different address pair)
# while the interface has not, so `iface` alone cannot see it and the decision
# rests entirely on net_id vs last_net_id. The proxy is correct and
# bind_interface still matches, so the right answer is the "no reload needed"
# log — a reload here would be the bug.
PARITY_SCENARIO=watch-net-moved ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | no reload needed, skip
# The reload branch, and the one whose message was wrong: the interface has NOT
# moved, the system proxy is simply no longer pointing at rowt. This used to log
# "network change (iface 'en0' -> 'en0')" — an interface that had not moved, in a
# message about the interface moving. Four real divergence bundles read that way.
PARITY_SCENARIO=watch-proxy-repoint ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | no longer points at rowt
# The default probe URL is a NAME, so this is the one case that resolves it at
# the NIC's DHCP resolver and pins the answer with --resolve (the other cases
# probe 127.0.0.1 and skip the lookup); a portal page under that URL must still
# read as the drop.
PARITY_SCENARIO=captive-dhcp-dns watch tick | captive portal detected — dropping system proxy
# The re-probe burst: the sandbox has no watch.net, so every tick is "just
# moved", and ROWT_CAPTIVE_RETRY=0,0 asks for two more probes of a URL that
# never answers. Nothing to log — the burst is silent by design — so the trace
# is what pins it: three probes, and three unknowns still hands-off.
ROWT_CAPTIVE_RETRY=0,0 ROWT_CAPTIVE_URL=http://127.0.0.1:9/x watch tick | probes=3
# A garden that blocks DNS rather than hijacking it. The named probe never gets
# a request out, so the verdict comes entirely from the DNS-free fallback; this
# is the case that took six real minutes to detect before that existed.
PARITY_SCENARIO=captive-no-dns watch tick | captive portal detected — dropping system proxy
# A Wi-Fi with no exit (2026-10-26, rowt #s19/#s21): the router is up, the
# tunnel probe fails for the third tick, the captive probe reaches nothing and
# the gateway is silent (no netstat answer, so no ping). Phase two must HOLD and
# say what the NIC and its gateway answered, in rowt status's own words — not
# reload, which is what this world got before.
PARITY_SCENARIO=watch-no-exit ROWT_CAPTIVE_URL=http://127.0.0.1:9/x watch tick | nothing answers over en0, not even its gateway
# The 2026-10-20 divergence (rowt #s57): the interface is named but has no
# address by the time the tunnel would be probed. The shell returns before its
# probe and resets the streak, logging nothing — so watch.last is the proof it
# got there. The shadow used to hand the planner a FAILED probe instead.
PARITY_SCENARIO=watch-offline-probe ROWT_IFACE=en0 ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | last=offline
# rowt #s36: a dead pinned server holds instead of reloading, said in full on
# the first tick and in one line after. The alive and udp worlds (the arm NOT
# firing) are cli-diff cases only: their 2100 recovery stamp lands on the
# cooldown line, whose "N s ago" is the shell's clock against the planner's.
PARITY_SCENARIO=watch-pin-dead ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | so the watchdog holds instead of reloading
PARITY_SCENARIO=watch-pin-dead-name ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | 203.0.113.10:443 does not accept a TCP connection over en0
PARITY_SCENARIO=watch-pin-held ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | pinned server alpha still dead
PARITY_SCENARIO=watch-pin-dead-failover ROWT_CAPTIVE_URL=http://127.0.0.1:8099/success watch tick | with --failover the follower moves off alpha as soon as another server answers, and back when alpha does
