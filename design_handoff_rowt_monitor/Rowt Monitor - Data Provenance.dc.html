Rowt Monitor — Data Provenance

Where every dynamic element gets its information

This document maps each moving part of the rowt monitor terminal interface to the upstream source it reads. The monitor is strictly an observer — it never mutates routing, servers, or the proxy. Every on-screen value is derived, on a fixed cadence, from one of the sources below.

Upstream sources
clash APILocal control plane on 127.0.0.1:9090 — the /traffic, /connections and /proxies (delay) endpoints. config~/.config/rowt/host.json — run mode, bind interface, rule set. statestate/servers.json — the outbound server pool and last probe results. logslog/lane-*.log — per-lane connection-failure events. systemHost OS — process uptime, system-proxy toggle, active interface. ui stateOperator-local view state — never sent upstream.

Refresh model

The interface repaints on a 2-second tick. Instantaneous values (rates, latency) are sampled each tick; historical shapes are computed over rolling buffers — a 26-sample ring for throughput and per-lane history, and a selectable time window for errors. Pausing (p) freezes sampling so figures can be read.

Lanes panel routing outcome

A lane is a routing outcome — which rule class a connection matched. The three rate lanes share one bar scale so they are directly comparable; the block cell reports a count rather than a rate.

ElementSourceDerivation
lane rate + barclash APISum of download rate across connections routed through that lane; bar = rate ÷ shared peak of the three rate lanes.
lane conn countclash APINumber of active connections whose matched rule falls in that lane.
block countclash APIConnections matched to the block rule (sinkholed or refused) — carries no throughput by definition.

Errors panel log/lane-*.log

Failure events are read from the per-lane logs and aggregated by domain over a rolling window (5m · 10m · 1h · 24h, cycled with w). Each row is one destination that failed within the window.

ElementSourceDerivation
N failed · M domainslogsCount of failure events, and distinct destination domains, within the window.
window tabsui stateSelected rolling window — filters which log events are counted.
countlogsFailures for that domain in the window.
reasonlogsFailure class from the log line — timeout, reset, refused, dns; colored by severity.
lane dot + domainlogsThe lane the failed connection belonged to (dot color) and its destination domain.

Not data-driven

The rowt ASCII banner, panel captions (┤ … ├), the keyboard-shortcut overlay (?), and all layout chrome are static presentation. Bold weight and color are terminal cell attributes used for emphasis and severity — they encode the same underlying values described above, not additional data.
